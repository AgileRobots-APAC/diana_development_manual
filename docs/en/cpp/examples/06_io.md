# 06 I/O

This example reads `board/di0`, `board/do0`, `board/ai0`, `board/ao0`, and bus electrical data by default. It writes output only when explicit arguments are supplied.

```bash
./build/bin/06_io --model diana7 --ip 192.168.10.75
./build/bin/06_io --model thor12 --ip 192.168.10.75 --set-do=1
./build/bin/06_io --model thor12 --ip 192.168.10.75 --set-ao=2:0.0
```

| API | Purpose |
|---|---|
| `readDI` / `readDO` / `writeDO` | Read digital input/output and optionally write digital output |
| `readAI` / `readAO` / `writeAO` | Read analog input/output and optionally write analog output |
| `readBusCurrent` / `readBusVoltage` | Read bus current and voltage |

## Example Call Flow

Connect and validate joint count → read and print I/O and bus data → check optional write arguments → write and print return values → release resources.

### Key Source Snippet

```cpp
int di = 0, ai_mode = 0;
double ai = 0.0;

if (readDI("board", "di0", di, ip) == 0)
    std::cout << "board/di0 = " << di << "\n";
if (readAI("board", "ai0", ai_mode, ai, ip) == 0)
    std::cout << "mode=" << ai_mode << ", value=" << ai << "\n";

const int do_ret = writeDO("board", "do0", value, ip);
const int ao_ret = writeAO("board", "ao0", mode, output, ip);
// V3.3: output range is 4–20 when mode=1 and 0–10 when mode=2.
```

```{warning}
Before writing I/O, confirm pendant AO configuration, terminal wiring, external device state, and allowed output range.
```

## API Usage and Call Examples

### `readDI` / `readDO` / `writeDO`

````{container} api-example-block

| Function | Prototype | Return Value |
| --- | --- | --- |
| `readDI` | `int readDI(const char *groupName, const char *IOName, int &value, const char *strIpAddress = "")` | `0` on success, `-1` on failure. |
| `readDO` | `int readDO(const char *groupName, const char *IOName, int &value, const char *strIpAddress = "")` | `0` on success, `-1` on failure. |
| `writeDO` | `int writeDO(const char *groupName, const char *IOName, int value, const char *strIpAddress = "")` | `0` on success, `-1` on failure. |

| Parameter | Direction / Type | Meaning |
| --- | --- | --- |
| `groupName` | In, `const char*` | I/O group name, for example controller board `board`. |
| `IOName` | In, `const char*` | I/O name, for example `di0` or `do0`; availability depends on controller configuration. |
| `value` | Out reference for reads, input `int` for writes | Digital value. Typically `0` means low/off and `1` means high/on, but the final meaning depends on wiring and external device logic. |
| `strIpAddress` | In, `const char*`, default `""` | Robot IP. An empty value is only appropriate for single-arm connections. |

`readDI(group_name, name, value, ip)` and `readDO(group_name, name, value, ip)` read one digital signal. `writeDO(group_name, name, value, ip)` writes a digital output. `board` is the group name; `di0` and `do0` are signal names and depend on controller configuration.

This example calls `writeDO` only when `--set-do` is given explicitly. Before writing, confirm the terminal, signal level, external power supply, PNP/NPN type, and peripheral action logic, and do not connect test outputs to unreviewed actuators.

```{rubric} Call Example
```

```cpp
int value = 0;
int ret = readDI("board", "di0", value, "192.168.10.75");
if (ret == 0) printf("di0: %d\n", value);

ret = writeDO("board", "do0", value, "192.168.10.75");
if (ret < 0) printf("writeDO failed!\n");
```
````

### `readAI` / `readAO` / `writeAO`

````{container} api-example-block

| Function | Prototype | Return Value |
| --- | --- | --- |
| `readAI` | `int readAI(const char *groupName, const char *IOName, int &mode, double &value, const char *strIpAddress = "")` | `0` on success, `-1` on failure. |
| `readAO` | `int readAO(const char *groupName, const char *IOName, int &mode, double &value, const char *strIpAddress = "")` | `0` on success, `-1` on failure. |
| `writeAO` | `int writeAO(const char *groupName, const char *IOName, int mode, double value, const char *strIpAddress = "")` | `0` on success, `-1` on failure. |

| Parameter | Direction / Type | Meaning |
| --- | --- | --- |
| `groupName` | In, `const char*` | I/O group name, for example `board`. |
| `IOName` | In, `const char*` | Analog I/O name, for example `ai0` or `ao0`. |
| `mode` | Out reference for reads, input `int` for writes | Analog mode. In the manual, `1` is current mode `4-20 mA`, and `2` is voltage mode `0-10 V`. |
| `value` | Out reference for reads, input `double` for writes | Analog value. Unit and valid range are determined by `mode`. |
| `strIpAddress` | In, `const char*`, default `""` | Robot IP. An empty value is only appropriate for single-arm connections. |

`readAI(group_name, name, mode, value, ip)` and `readAO(group_name, name, mode, value, ip)` read analog signals and return the analog mode. `writeAO(group_name, name, mode, value, ip)` writes analog output by mode.

The manual specifies `mode=1` as current mode (4–20) and `mode=2` as voltage mode (0–10); values outside the range fail. The example therefore writes a zero voltage output as `--set-ao=2:0.0`, but whether that is safe still depends on the peripheral logic.

```{rubric} Call Example
```

```cpp
int mode = 2;
double value = 0.0;
readAI("board", "ai0", mode, value, "192.168.10.75");
readAO("board", "ao0", mode, value, "192.168.10.75");

// 1: 4–20 mA; 2: 0–10 V
ret = writeAO("board", "ao0", mode, value, "192.168.10.75");
if (ret < 0) printf("writeAO failed!\n");
```
````

### `readBusCurrent` / `readBusVoltage`

````{container} api-example-block

| Function | Prototype | Return Value |
| --- | --- | --- |
| `readBusCurrent` | `int readBusCurrent(double &current, const char *strIpAddress = "")` | `0` on success, `-1` on failure. |
| `readBusVoltage` | `int readBusVoltage(double &voltage, const char *strIpAddress = "")` | `0` on success, `-1` on failure. |

| Parameter | Direction / Type | Meaning |
| --- | --- | --- |
| `current` | Out reference, `double&` | Controller bus current reading. |
| `voltage` | Out reference, `double&` | Controller bus voltage reading. |
| `strIpAddress` | In, `const char*`, default `""` | Robot IP. An empty value is only appropriate for single-arm connections. |

`readBusCurrent(current, ip)` and `readBusVoltage(voltage, ip)` read controller bus electrical data for diagnostics. They are not substitutes for external power ratings or wiring checks. A successful API return also does not mean that the field wiring or load state is safe.

```{rubric} Call Example
```

```cpp
double current = 0.0;
double voltage = 0.0;
readBusCurrent(current, "192.168.10.75");
readBusVoltage(voltage, "192.168.10.75");
```
````
