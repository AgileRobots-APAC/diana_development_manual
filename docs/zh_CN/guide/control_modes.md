# 控制模型与模式选择

这一页不是具体接口清单，而是帮助开发者先判断“应该选哪类控制能力”。具体接口名称、参数和限制应在对应实现方式的编程指南或 API Reference 中确认。

| 需求 | 推荐控制方式 | 适用场景 |
|---|---|---|
| 让机器人到达明确目标点 | 目标点运动 | 点到点搬运、回零、到达拍照位或取放位 |
| 沿直线靠近目标 | 笛卡尔直线运动 | 插入、靠近工件、沿工具方向移动 |
| 只做短距离微调 | 点动 / Jog | 调试、示教辅助、低速找点 |
| 按速度连续移动 | 速度控制 | 人机交互、扫描、外部逻辑持续调节速度 |
| 高频更新目标位姿 | 在线伺服控制 | 视觉伺服、力位混合策略、外部规划器实时下发 |
| 直接控制或发送力矩 | 力矩控制 | 动力学实验、底层控制研究、特殊实时控制 |
| 根据接触力调整行为 | 力控 / 阻抗 | 打磨、装配、接触检测、柔顺控制 |
| 人手拖动机器人 | 自由驱动 | 示教、路径采集、姿态调整 |

## 轨迹类与实时类不要混用概念

轨迹类控制通常由控制器生成并执行完整运动；实时类控制依赖上位机持续更新目标。如果上位机更新周期、网络延迟或目标连续性无法保证，应优先选择轨迹类控制。

## 选择与切换原则

- 先使用目标点或直线轨迹完成工艺验证；只有确实需要外部闭环时再引入速度、伺服、力矩或力控模式。
- 速度控制和在线伺服都不是“一次下发后等待完成”的轨迹命令。开始前应准备连续目标源、丢包/超时策略和明确的停止条件。
- 进入力控、阻抗或自由驱动前，先确认工具负载、TCP、碰撞策略及现场安全边界；退出模式后再恢复普通位置控制流程。
- 同一时刻只让一个业务状态机拥有运动指令权限。模式切换、错误恢复和退出时，先停止当前运动并确认控制器状态，再下发下一类命令。

## 实时类控制在各接入方式中的对应

FCI 与 ROS 2 都支持下面五类实时控制输入。FCI 在实时回调中返回对应类型，ROS 2 则由控制器申请对应的命令接口；两者在同一时刻都只按一种控制输入工作。

| 控制输入 | FCI 回调返回类型 | ROS 2 命令接口 |
|---|---|---|
| 关节位置 | `franka::JointPositions` | 关节的 `position` 命令接口 |
| 关节速度 | `franka::JointVelocities` | 关节的 `velocity` 命令接口 |
| 关节力矩 | `franka::Torques` | 关节的 `effort` 命令接口 |
| 笛卡尔位姿 | `franka::CartesianPose`（可附带肘部参数） | `cartesian_pose_command` 命令接口（可附带肘部接口） |
| 笛卡尔速度 | `franka::CartesianVelocities`（可附带肘部参数） | `cartesian_velocity` 命令接口（可附带肘部接口） |

轨迹类控制在 ROS 2 中通常由 MoveIt 规划，再交给轨迹控制器执行。

```{warning}
实时控制的调用周期、前瞻时间和增益互相约束。参数范围、是否支持某模式及其退出方式必须以当前版本的 SDK 头文件和 API Reference 为准。
```
