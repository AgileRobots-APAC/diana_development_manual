# 状态、反馈与回调

不同 SDK 暴露状态的方式不同：有的通过回调推送，有的通过主动查询，有的通过实时数据流提供，还有的通过 ROS 话题提供。但开发时关心的状态类别是共通的。本页只解释数据处理边界，不定义具体 SDK 的回调签名。

| 状态类别 | 含义 | 常见用途 |
|---|---|---|
| 关节位置 | 每个关节的当前角度或位移 | 记录当前位置、运动前后校验、轨迹调试 |
| 关节速度 | 每个关节的当前速度 | 判断机器人是否仍在运动 |
| 关节电流 / 力矩 | 关节驱动侧负载信息 | 诊断负载、异常阻力或电机状态 |
| TCP 位姿 | 工具中心点的位置和姿态 | 笛卡尔运动调试、工艺位记录 |
| TCP 外力 | 末端测得或估算的外部力 | 接触检测、力控、工艺过程监测 |
| 碰撞 / 错误状态 | 控制器安全与异常标志 | 安全保护、故障诊断、流程中断 |
| I/O 状态 | 数字量、模拟量或扩展 I/O 状态 | 夹具、传感器和外部设备联动 |

## 状态处理建议

| 场景 | 建议 |
|---|---|
| 状态以回调到达 | 只做轻量拷贝、标志位更新或无阻塞日志 |
| 需要耗时计算或文件写入 | 放到业务线程处理，不要阻塞状态接收链路 |
| 需要最新状态快照 | 在状态接收处更新共享状态，业务线程按需读取 |
| 只偶尔读取一次状态 | 使用对应 SDK 的主动查询接口更简单 |

具体字段名、结构体名称和查询函数由各 SDK 或独立接口参考维护。

## 建议的状态机

不要只用“连接成功”判断机器人可运动。应把通信、控制器与业务状态分开维护，例如：

对 C/C++ SDK，状态回调通常提供关节位置/速度、电流或力矩、TCP 位姿、TCP 外力及碰撞等高频信息；主动查询适合启动校验、低频诊断和命令结果确认。无论使用哪种方式，都应在回调中保留最新时间戳，业务线程据此判断状态是否过期。

## 各接入方式的状态来源

| 接入方式 | 状态如何到达应用 | 说明 |
|---|---|---|
| C++ / Python SDK | 状态回调或主动查询 | 见上文 |
| FCI | `franka::RobotState`，来自 `read()`、`readOnce()` 或控制回调；模型数据来自 `franka::Model` | 在每个控制周期随回调到达，回调内不要阻塞 |
| ROS 2 | `diana_robot_state_broadcaster` 发布 `~/robot_state`（每个控制周期，1000 Hz）和一组便捷话题 | 便捷话题的 QoS 为 best effort，订阅方必须使用兼容的 QoS 才能收到 |

```{important}
回调不是安全功能的替代品。收到碰撞、错误或反馈中断后，应立即停止业务层继续下发命令，并按对应型号的安全规程处置现场。
```
