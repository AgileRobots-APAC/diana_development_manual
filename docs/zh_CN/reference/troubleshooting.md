# 故障排查

## 先保留现场信息

不同 SDK 获取错误的方式不同：可能来自错误回调、主动查询、异常、日志、ROS topic / service 返回值或 FCI 状态码。排查前先记录：

- 错误码与发生时刻；
- 机器人状态、控制方式和 IP 连通性；
- 最近一次下发的指令与关键参数；
- SDK `version` 文件、Example 版本和文档版本。

然后查看[完整错误码表](error_codes.md)，不要在信息丢失后反复重启或清错。

## 常见排查方向

### 网络 / 链路

重点关注 `-1001` 至 `-1015` 一类 socket、心跳、状态反馈、IP 未注册错误。

从物理层开始依次确认：控制 PC 是否接在控制柜 A 网口、网卡是否处于同一子网、能否 `ping` 通、控制器是否完成初始化，以及是否有另一个程序持有连接。不要把 D 网口或串口链路当作 SDK API 链路。

### 机械臂状态 / 安全

重点关注 `-2201` 之后的调用冲突、碰撞、急停、STO、保护停止、软硬限位等错误。

### 轨迹与运动学

`-2301` 之后包含规划、奇异、速度/加速度/jerk、逆解、轨迹插补等错误。

### 实时 / FCI

`-6001` 之后集中描述位置偏差、速度 / 加速度不连续、功率、力阈值和运动稳定性问题。

实时问题还应记录实际调用周期、最长周期、CPU 负载、网络抖动、目标点是否连续，以及中断后采用的停止策略。先降低速度、加速度和更新频率验证稳定性，再逐步接近工艺参数。

```{important}
V3.3.0 手册特别说明 `-2001` 和 `-2205` 的清除方式与普通错误不同。遇到这两类错误时，先看完整错误码页中的手册说明，不要只做重复清错操作。
```
